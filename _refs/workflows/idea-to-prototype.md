# Idea To Prototype

Use when a brief or validated direction should become a lightweight prototype package before delivery commitment.

1. State the prototype objective and the learning question it answers.
2. Identify the riskiest assumptions from the brief.
3. Select the minimum journey needed to test those assumptions.
4. Draft user flow, screen list, and wireframe descriptions.
5. Choose the builder target: Claude Code, Lovable, Bolt, Figma, slides, or manual clickable mockup.
6. Write a prompt that includes domain context, target users, key flows, data assumptions, states, and constraints.
7. Explicitly exclude production concerns that do not affect learning.
8. Define the validation method and next skill: `experiment`, `validate`, or `spec`.
