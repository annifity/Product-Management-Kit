# Spec To Delivery Plan

1. Start from confirmed scope and requirements.
2. Prioritize requirements using `_refs/checklists/prioritization.md` when sequencing is disputed.
3. Group requirements into epics.
4. Slice release scope by user value, risk reduction, and dependency order.
5. Identify design, data, integration, QA, security, privacy, accessibility, operational readiness, and rollout work.
6. Build or update traceability: REQ-ID -> STORY-ID -> AC-ID -> UAT-ID -> RELEASE CHECK.
7. Mark blockers, decision owners, approvers, accepted risks, and review dates.
8. Prepare grooming questions for Backend, Frontend, QA, Data, Security, and Architecture when needed.
9. Recommend story writing and UAT sequence.
