# Workshop Facilitation Workflow

Use for interactive PM sessions, advisor-style workflows, discovery workshops, prioritization sessions, story mapping, and strategy alignment.

## Entry Modes

Start by offering one mode.

| Mode | Use When | Behavior |
|---|---|---|
| Guided | User wants structured facilitation | Ask one question per turn and wait. |
| Context dump | User has notes, docs, or meeting context | Let user paste context, then ask only material gaps. |
| Best guess | User wants speed and accepts assumptions | Infer missing details, label assumptions, and continue. |

## Facilitation Rules

- Start with a brief heads-up: estimated time, number of sections, and expected output.
- Ask one question per turn.
- Use plain-language questions; avoid framework jargon unless already introduced.
- Show progress labels such as `Context Q1/5`, `Scoring Q2/4`, or `Decision Q1/2`.
- Offer concise numbered options when they reduce user effort.
- Accept `1`, `#1`, `1,3`, `1 and 3`, or custom text.
- Ask follow-ups only when the answer materially changes the recommendation.
- Answer interruption/meta questions directly, restate progress, then resume.
- If the user says stop or pause, halt and wait for resume.
- End with decisions made, assumptions, open questions, and recommended next artifact.

## Decision Points

Use numbered recommendations only at decision points:

- After context synthesis.
- After scoring or maturity assessment.
- When selecting prioritization method, experiment type, workshop path, or next artifact.

## Output

- Session objective.
- Inputs captured.
- Decisions made.
- Assumptions to validate.
- Open questions and owners.
- Recommended next step: `po-brainstorming`, `po-spec`, `po-plan`, `user-story`, `uat`, or `docs`.

## Pitfalls

- Asking several questions in one turn.
- Recommending after every answer.
- Hiding progress.
- Ignoring the user's selected mode.
- Treating best-guess assumptions as facts.
