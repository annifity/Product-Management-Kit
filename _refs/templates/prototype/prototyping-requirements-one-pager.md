# PRO - Prototyping Requirements One-Pager

Use this prompt-ready one-pager to create a runnable frontend prototype with mock data. PRO is not a PRD, not a full product spec, not an engineering handoff, and not a production-ready build request. Keep the final PRO at or below 500 words and use exactly these 11 sections.

## 1. Problem Statement And Goal

- [Customer problem or need in 1 sentence.]
- Goal: [primary prototype goal and why it matters.]

## 2. Target Users And Use Case

- [Primary users and context.]
- Core use case: [main scenario or user story to prototype.]

## 3. Key Requirements And Features

- [3-5 must-have prototype capabilities or UI components.]
- [For AI products, include model-visible capabilities or data inputs.]

## 4. AI Considerations

- [AI behavior, tone, accuracy expectation, latency, context/data inputs, fallback, or N/A.]

## 5. Golden Paths

- Path 1: [core happy path.]
- Path 2: [important variant, edit, review, or confirmation path.]
- Path 3: [AI clarification, exception, or optional alternate path.]

## 6. Edge Cases And Risks

- [2-3 realistic edge cases, red flags, missing data, unsupported AI requests, privacy, or trust risks.]

## 7. Assumptions And Constraints

- Assumption: [what must be true about users, data, feasibility, or integrations.]
- Constraint: [demo-only, mock data, no backend, no production security, or other prototype boundary.]

## 8. Success Metrics Or Criteria

- [Qualitative or quantitative success signal: task completion, clarity, usefulness, response quality, satisfaction, time, edit rate, or trust.]

## 9. Non-Goals

- [What this prototype will not build, automate, integrate, or validate.]

## 10. Prompt-Ready Input For AI Prototyping

- For the selected frontend prototype builder (for example `sdcorejs-agent`): [first UI layout, simulated user flow, mock data shape, output format, and optional concept variations.]

## 11. Next Steps

- [Testing plan, feedback session, experiment, decision point, or PRD/spec trigger after learning.]
