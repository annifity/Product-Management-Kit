# PO Review

Use this when the user asks whether an artifact is ready, complete, testable, clear, or safe to hand off.

## Process

1. Identify the artifact type: PRD, spec, story, UAT, change plan, or release package.
2. Review against the relevant checklist.
3. Separate blocking issues from improvements.
4. Provide inline fixes when the user asks for correction, not only critique.
5. Recommend the next phase: revise, plan, execute, UAT, or ship.

## Output

- Verdict: ready / needs revision / blocked
- Blocking issues
- Important improvements
- Inline fixes or suggested edits
- Residual risks
- Next action
