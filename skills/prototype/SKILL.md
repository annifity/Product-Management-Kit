# Prototype

Use this to turn a brief into a lightweight prototype package. The goal is learning, not production delivery.

## Process

1. Read the brief, target users, success metrics, constraints, and relevant memories.
2. Identify the riskiest assumptions the prototype should expose.
3. Define the minimum user flow and screen list needed to learn.
4. Draft wireframe descriptions and prototype prompts for the selected builder.
5. State what the prototype deliberately excludes.
6. Recommend `experiment`, `validate`, or `spec` as the next step.

## Output

- Prototype objective
- Learning questions
- User flow
- Screen list
- Wireframe descriptions
- Prototype builder prompt
- Out-of-scope production concerns
- Next validation step
